# 公司基本資料

## 用途

ADMIN `/company-profile` 維護本公司的**公司名稱、統一編號（8 碼）、稅籍編號（9 碼）**（必填），以及負責人、營業地址（郵遞區號、縣市、鄉鎮市區、路街巷弄門牌四欄）、主管稽徵機關、申報聯絡人／電話／Email（選填，只記錄顯示，系統邏輯不使用），固定只有一筆（一個公司一個資料庫）。
F09 格式 21 申報檔由 `DatabaseCompanyProfileProvider` 讀取：統編寫在每一行的買受人統編與檔名（`統編.TXT`），稅籍編號寫在每一行開頭。
這取代 `F_Schema補充建議_v1.8.md` §5 原本建議的 `COMPANY_BAN`／`COMPANY_TAX_REG_NO` 設定值（2026-11-04 使用者決定改用頁面維護）。

## 畫面與規則

- 查看頁顯示全部欄位（選填未填顯示「未提供」）與最後修改時間；尚未設定時提示「申報資料頁無法產生格式 21 申報檔」。
- 設定／修改表單三個必填欄位：統一編號驗算檢查碼；選填欄位只檢查長度，Email 有填時檢查格式；稅籍編號沒有公開檢查規則，只驗 9 碼並**輸入兩次**，一致才存檔（確認欄不帶入原值）。
- 營業地址：縣市與鄉鎮市區從下拉清單選（選縣市後只列該縣市的區），3 碼郵遞區號自動帶出；兩者須同時選或同時不選。郵遞區號一律由伺服器依清單帶出，不採用表單送來的值。清單在 `app/schemas/tw_postal_codes.py`，來源為中華郵政「臺灣地區郵遞區號前3碼一覽表」103.12.25 版（23 個縣市含南海諸島、368 個鄉鎮市區），中華郵政更新時重新轉出即可，不需改 Schema。
- 修改以 `updated_at` 版本比對，他人已先修改時拒絕；第一次設定時若他人已先設定也拒絕，不覆蓋。
- 寫入限精確同源表單，拒絕未知／重複欄位；建立者與修改者取自 Session。

## 權限

- 程式功能代碼 `company.profile`，對應 DB 功能目錄 `company_profile`（`admin_login_service.CATALOG_CODES`），公司層級資料（`COMPANY_CATALOG_CODES`）。
- 只有查看、修改兩項操作；每個路由依操作驗權，寫入在同一交易內重新驗證部門勾選（比照供應商管理）。
- 只有修改權限、沒有查看權限時可儲存，但結果頁不顯示公司資料。
- 側欄依目前部門的勾選顯示「🏛️ 公司基本資料」。

## F09 讀取

| 情況 | F09 使用的公司資料 |
|---|---|
| 已設定 | 資料表的值 |
| 尚未設定、資料表尚未建立或讀取失敗 | 空白，申報頁顯示「尚未設定本公司基本資料」並擋下產檔，**不以測試統編代替** |
| 沒有資料庫連線（離線測試、未經 START） | 示範值（`HardcodedCompanyProfileProvider`） |

## 正式啟用步驟

1. 資料庫維護者確認 `alembic_version` 為 `5e8b11d0a941`（供應商），再取得授權執行 API migration `8ef487f17b06`：建立 `public.company_profile`（RLS、REVOKE PUBLIC／anon／authenticated）並新增功能目錄 `company_profile`，不寫入公司資料、不授予部門權限。
2. 由有部門管理權限的人到「部門管理」幫財務部勾選「公司基本資料」的查看／修改。
3. 財務到 `/company-profile` 設定公司資料，再到申報資料頁確認批次卡片不再出現公司資料錯誤。

**注意**：新版程式部署後、migration 執行前，F09 讀不到資料表會擋下產檔（原本以測試統編產出的檔案本來也不能申報）。
