# 管理站內建歡迎頁與避免首頁漏授權

日期：2026-10-28。使用者核定有效 ADMIN 身分沒有業務功能時，允許登入但只能查看歡迎頁；不需初始管理員，已使用網站 Session 與部門勾選驗證。

## 固定規則

- 管理站入口 / 及登入成功後固定先到 /welcome，忽略 next 的目的地，不直接進入其他頁面。
- welcome 是內建基礎能力，只有 VIEW，不是部門矩陣的可選功能。既有部門、新增部門與切換後的有效部門都適用，不需每次建立部門時補 seed 或 grant。
- 不開放內容新增、修改或刪除端點；使用者即使是系統管理員，也不能以 welcome 的 CREATE／EDIT／DELETE 取得權限。
- 歡迎能力只有問候畫面，沒有公司資料權限；不能用它授權帳號、發票或全域資源。基本 ADMIN 資格、UUID、Session、期限及憑證版本仍要由正式來源驗證。
- 生產／預覽環境不是匿名歡迎頁：未登入導向登入，無效／過期／前台或非 ADMIN 身分仍拒絕。只有現有明確核定的本機初始化模式可匿名，雲端的配置 CRUD 仍關閉。

## 登入與無功能帳號

EModule.login 仍由 B 發行 Session，驗證相同 user UUID、ADMIN 用途及權限快照完整性。僅針對完整有效快照確認沒有任何業務功能的 NoAdminFunctionsError 允許成功登入；錯誤身分、缺正式認證、錯誤／不完整權限資料等仍撤銷剛建立的 Session 並拒絕，不假登入。

其他 /workspace、/account、配置與業務路由原有驗權不變。沒有功能者的正式歡迎頁側欄只有歡迎頁及登出；有有效功能才依權威投影增加入口。歡迎 GET 的問候不依賴 G 供應業務功能選單；若選單來源不可用，只隱藏其他入口，不放寬其他路由。

正式 B／G adapters 目前仍未組裝，所以目前真實登入提交仍可能 503；此批是 E 端規則與接點驗證，不是正式認證已完成。LOCAL_SETUP_ENABLED 仍為 True，未自動切回登入限制。

## 部門與功能畫面

部門內容頁固定顯示一列歡迎頁，查看已勾選且不可取消，其他三項停用。即使 DB 沒有 welcome 目錄或授權列也會顯示並套用內建規則，不讀寫全組資料做批次回填。

若既有目錄已有 function_code=welcome，畫面不顯示重複列，隨使用者儲存本部門時，把該列保存為 view=true、create/edit/delete=false。既有其他部門的原始 DB 旗標不由代理更動，E 內建能力不以這些原值作授權來源。偽造表單撤銷查看或追加寫入會被伺服器拒絕，而非僅停用 checkbox。

功能目錄中的 welcome 標示內建唯讀；伺服器拒絕修改、停用或另行建立 welcome 目錄。它不是跨前台／管理站的共用業務功能；本次只處理 ADMIN，保留 DB 既有平台值而以畫面清楚說明管理站內建首頁。

WELCOME_CAPABILITY 保留在程式內，不塞入 G 可選 REGISTRY 以改變完整性協定；supported_actions(welcome) 回 VIEW，共用 require_permission 實際執行內建唯讀規則。其他未知代碼仍拒絕，原三項 E 可選管理功能不變。

## 恢復正式模式前

歡迎預設只解決首頁漏勾，不會自動把任何人變成系統管理員。帳號建立者、資訊部／系統部成員、職稱或 Email 都不自動取得管理資格。

目前歡迎頁固定唯讀；登入不以業務權限為門檻，沒有勾選其他功能仍可進歡迎頁。配置功能依目前部門四操作勾選，不再要求初始管理員或額外管理資格。
