# 06_E 登入與部門功能權限

## 目前流程（2026-10-28）

1. 驗證 Email／密碼及帳號、員工、部門有效性。
2. 讀取本人目前部門的功能設定，組合網站 Session。初次登入以帳號既有主要部門為目前部門，不合併多部門權限。
3. 查看、新增、修改、刪除各依該部門的對應勾選，不從查看推定其他操作，不再要求身分、職務或初始管理員。
4. 登入成功固定進 /welcome；沒有其他功能也能查看歡迎頁，歡迎頁不能修改。
5. 各功能入口在伺服器驗證對應操作，不能只靠隱藏選單。權限勾選變更後下一次操作重新讀取，不能沿用 Session 舊許可。

LOCAL_SETUP_ENABLED=False，已關閉既有本機免登入例外。本次以既有 UUID 帳號及部門資料直接串接，不新增 B／G 核心、角色、Schema 或資料表。

## 網站 Session

沿用本站既有 itsdangerous 套件產生簽章 Cookie，資料包含 UUID、目前部門、憑證版本、到期時間及功能四操作 bitmask（查看=1、新增=2、修改=4、刪除=8）。不含密碼、雜湊或 API Key；不使用 localStorage／sessionStorage。Cookie 為 HttpOnly、SameSite=Lax、Path=/、無 Domain、無 Max-Age／Expires；正式環境 Secure。簽章資料可編碼讀取，不能把它當成加密保管機密。

本機簽章金鑰只在目前 ADMIN 程序記憶體，服務重啟／程式重載後需重新登入，不讀寫公司密鑰。雲端沿用已存在的 SESSION_SECRET_KEY 設定；本次不修改或部署雲端設定。

登出清除目前瀏覽器 Cookie，不新增 DB Session 或撤銷表；已複製的有效 Cookie 不因清除瀏覽器而在全站撤銷，仍受簽章期限、帳號有效性、credential_version 與部門有效性檢查。這是網站 Session 的目前行為，不宣稱已實作資料庫 Session 撤銷。

## 使用既有資料

- invoiceguard_identity.user_accounts：驗帳密及帳號有效性。
- public.user_profiles：確認員工有效。
- public.user_departments／public.departments：確認目前所屬有效部門。
- public.app_functions／public.department_permissions：讀功能啟用、平台及 can_view／can_create／can_edit／can_delete。
- 登入的唯一寫入：user_accounts.last_login_at。登入失敗、登出及讀權限不新增或修改 DB 資料；不使用 user_sessions 或新增權限欄位。

功能對應沿用目前目錄：accounts → 帳號、department → 部門及同頁授權區、functions → 功能管理。它們維持既有配置頁資料範圍，勾選許可即可操作；其他業務模組仍需把其真正路由／操作接上對應功能，建立目錄不會自動產生程式。

網站 Session 有一份登入當時的功能快照，伺服器操作以 adapter 重新讀取的目前部門設定為準。其他組不得只憑前端傳入的 user_id、角色 Header 或自行解碼 Cookie 決定許可；可沿用 EModule.identity／check 及固定 Capability 接點。既有 /system/* 的早期 journal／UOW 接口與其他業務頁不因本批而全部完成。

## 操作入口

- /login：登入。
- 左側「帳號管理」下一項為「登出」：使用既有 POST /logout，清 Cookie 後返回 /login；沒有帳號管理許可時仍在側欄底部顯示。
- /welcome：登入後第一頁。
- /accounts：按部門帳號管理勾選。
- /department：按部門管理勾選，編輯內容頁包含授權區。
- /functions：按部門功能管理勾選。

未登入先導向登入，未勾選則拒絕。停用、僅前台或尚未接上真實程式的功能不會自動成為可用後台入口。原有同源、表單驗證與衝突保護保留；配置寫入沿用原服務交易，操作前同交易取鎖與驗權，登入本身不改寫配置。

## 取消本次 Session 所屬部門時

在帳號頁取消所屬部門並儲存，如果移除的正是原 Session 選取的部門，下一次請求會要求重新登入；不是儲存失敗。重新登入後採用帳號既有主要部門並重新讀取其勾選。若主要部門沒有配置功能許可，就只顯示歡迎及登出；不沿用被移除部門的舊許可。已勾選但尚未連接實際路由的業務項目，仍只保留設定，不自動出現入口。


## 2026-10-28 左側選單改依部門授權目錄顯示

- 原因：網站 Session 已讀取自行新增功能的四項許可，但舊側欄只取固定 registry，造成部門已授權的三聯式發票功能完全不出現。
- 結論：歡迎頁、配置頁與 E 工作台共用側欄投影。每次請求重新驗證目前帳號／所選有效部門，讀取啟用且適用 ADMIN／兩站、至少勾選一個操作的功能，使用資料庫功能名稱呈現；不聯集其他部門。
- 已有固定程式路徑且獲授權查看的功能可點選；已接線但只允許其他操作的項目顯示「未授權查看」。尚未接線的目錄功能顯示名稱及「尚未接線」，不產生可點連結、不從任意功能代碼拼出網址，也不代表發票業務已完成。
- 撤銷四操作、停用功能或移除部門資格後，下次請求即反映；歡迎頁與登出仍保留。帳號管理與登出相鄰。長名稱會換行，手機側欄避免待接線項目的高度拉伸其他按鈕。
- 僅新增側欄讀取及呈現；不修改正式資料、資料表、帳號身分或部門授權，不新增發票 CRUD，不替代各功能既有伺服器操作驗權。
